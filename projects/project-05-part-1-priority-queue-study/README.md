## 3. Implementation Details

### 3.1 Overview

This project implements an additional workload profile, Batch-then-Drain, for the purpose of benchmarking a priority queue framework with multiple implementations: .

The profile workload simulates an offline heap loading where all elements are known at the time of execution. It inserts all keys at once and then extracts them until the queue is empty. This is a model for heapsort and offline scheduling.
### 3.2 Executable + Directory Structure

- **Generator executable:** `trace-generators/batch_then_drain/main.cpp`
- **Trace output directory:** `traces/batch_then_drain/`
- **Replay harness:** `harness/main.cpp`
- **CSV output directory:** `csvs/`

Each `(N, seed)` pair produces one `.trace` file with filenames like:

- `batch_then_drain_N_<N>_S_<seed>.trace`

### 3.3 How the Generator Works

The generator uses a single fixed seed generated by the following:

`std::mt19937 gen(seed); std::uniform_int_distribution<int> dist(lo, hi);`

- The seed is embedded in the filename of the trace file.
- For each N:
  1. Emit `N Inserts` with random keys.
  2. Emit `N find/deleteMins` during the drain phase
- The sequence always has exactly **2N operations**.

### 3.4 Running the Project

All commands below assume a Linux environment with `make`, `cmake`, and a C++17 compiler installed.  
They should be run from the project root directory:

`priority-queue-study/`

To build and run only the trace generator, use the following command:

`make traces`

To build and run only the harness to generate a csv file, use the following command:

`make csv`

To build everything, generate the batch-then-drain traces, and produce the CSV in a single command:

`make`

This will:

1. Configure CMake into `build/` (if needed).
2. Build the `batch_then_drain_trace` trace generator and the `harness` executable.
3. Generate all batch-then-drain traces under:
   `traces/batch_then_drain/`
4. Replay those traces with all four implementations and write the timing results to:
   `csvs/batch_then_drain.csv`

The csv data can then be copied into the chart generator html found at the follwoing:

`charts/pq_multi_impl_anchor_heap_tooltips_btd.html`

### 3.5 CSV Fields (expected values)

| Column         | Meaning                                  |
| -------------- | ---------------------------------------- |
| impl           | PQ implementation tested                 |
| profile        | batch_then_drain                         |
| trace_path     | path to source `.trace` file             |
| N              | number of inserts and number of extracts |
| seed           | RNG seed used                            |
| elapsed_ms     | total runtime for replay                 |
| ops_total      | total operations in trace (= 2N)         |
| inserts        | always N                                 |
| find/deleteMIn | N                                        |

### 3.6 Visualization

I used the provided `pq_multi_impl_tooltips.html` plotting tool:

- Load the CSV generated from the harness.
- Toggle the **N log N baseline** to compare shapes.
- Expected curve shapes:
  - **Binary heap:** tracks N log N shape almost exactly.
  - **Linear baseline:** grows roughly linearly.
  - **Binomial queue:** also like Binary heap, but can not compete with large N.
  - **Quadratic oracle:** grows sharply, (run with N = 2^15).
